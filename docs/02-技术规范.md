# 技术规范

## 技术栈

- Next.js、React、TypeScript。
- Tailwind CSS 负责布局与样式。
- Framer Motion 负责角色、拖拽反馈和结果动画。
- SVG 负责临时场景、瓶子、酒杯与可缩放视觉。

首次创建工程前必须先检查项目目录中是否已有初始化结果、依赖缓存或可复用文件；确认后再决定是否安装依赖。

## 状态边界

- `DrinkState`：配料比例、总比例、Flavor Profile 和液体视觉状态。
- `DragState`：当前配料、是否拖动、是否在 Pour Zone、是否倒酒。
- `SceneState`：`mixing | serving | result`。
- 所有配方变化必须经过 `incrementIngredient(id, deltaPct)` 或未来的 `setRecipe()`。
- UI 不直接写入颜色、风味或液面；这些值由 `mixEngine` 根据配方计算。
- 满杯上限、倒酒步长、倒酒频率、Serve 时长和结果编号集中放在 `web/lib/gameConfig.ts`，组件不得重复硬编码。

## mixEngine 规则

- 风味和 RGB 使用配料百分比加权平均。
- 酒精度纳入 Alcohol 输出，所有输出归一化到 `0–1`。
- `totalPct === 0` 时返回稳定的安全默认值，不出现 `NaN`。
- `amountPct` 为整数，单次倒酒增加 1，合计最大 100。
- 计算函数保持纯函数，便于独立测试和后续 AI 配方复用。

## 指针与计时器规则

- 使用 Pointer Events 统一鼠标、触控和触控笔。
- 处理 `pointerdown`、`pointermove`、`pointerup`、`pointercancel`。
- 倒酒计时器只能存在一个；进入 Pour Zone 时启动，离开、松手、取消、Serve 和组件卸载时清理。
- 达到 100% 后立即停止计时器。
- 拖拽结束后恢复酒瓶视觉和原始位置。

## 可替换资产规则

- 场景、章鱼、瓶子与玻璃分别封装，禁止将完整画面烘焙成单张不可拆分背景。
- 组件通过稳定容器、`object-fit` 和语义化尺寸适配后续 WebP/PNG 资产。
- 资产路径集中管理；替换正式资产时不改业务状态逻辑。
- `web/lib/visualAssets.ts` 是视觉资产路径的唯一映射入口；组件中不散落硬编码路径。
- SVG/CSS 占位结构是 MVP 的必备回退层。生成的 PNG/WebP 只作为独立增强图层，加载失败时隐藏，不得导致场景、交互或信息缺失。
- 背景、酒保、八个酒瓶、酒杯和结果卡底板必须保持独立资产槽位；背景图不得包含角色、酒杯、酒瓶、Flavor Profile、按钮或文字。
- 正式资产替换只允许更改集中路径和对应样式适配，不修改配方、拖拽、倒酒、Serve 或 WebMCP 逻辑。

## WebMCP 工具

新站点在浏览器支持 `document.modelContext` 时注册以下页面级工具，并复用与可见界面相同的状态和动作：

- `read_drink_state`：只读当前配方、风味和液体状态。
- `set_drink_recipe`：批量设置合法配方，总量按现有 mixEngine 规则限制为 100%。
- `serve_drink`：仅在混合阶段且杯中非空时执行 Serve，并等待结果卡完成显示。

不支持 WebMCP 的浏览器必须静默跳过注册，不能影响正常游戏。
