# 技术规范

## 技术栈

- Next.js、React、TypeScript。
- Tailwind CSS 负责布局与样式。
- Framer Motion 负责角色、拖拽反馈和结果动画。
- SVG 负责临时场景、瓶子、酒杯与可缩放视觉。

首次创建工程前必须先检查项目目录中是否已有初始化结果、依赖缓存或可复用文件；确认后再决定是否安装依赖。

## 状态边界

- `DrinkState`：配料比例、总比例、Flavor Profile、`mood.valence` 和液体视觉状态。
- `Ingredient.moodValence` 使用 `-1..1`：`-1` 为忧郁/深沉，`0` 为平衡，`1` 为喜悦/明快。`mixEngine` 按实际配料百分比加权生成 `DrinkState.mood.valence`，组件只读取结果。
- 情绪参数属于叙事型感官元数据，不能由 UI 临时推断，也不能显示为医学、心理学或酒精作用结论。
- `DragState`：当前配料、是否拖动、是否在 Pour Zone、是否倒酒。
- `SceneState`：`mixing | serving | result`。
- `GlassType`：`highball | tumbler | cocktail | collins`，由界面状态独立维护，不进入 `DrinkState` 和 mixEngine。
- 所有配方变化必须经过 `incrementIngredient(id, deltaPct)` 或未来的 `setRecipe()`。
- UI 不直接写入颜色、风味或液面；这些值由 `mixEngine` 根据配方计算。
- 满杯上限、倒酒步长、倒酒频率、Serve 时长和结果编号集中放在 `web/lib/gameConfig.ts`，组件不得重复硬编码。
- Serve 时由 `GameViewport` 冻结最终 `DrinkState` 并并行启动文案请求；`DrinkCard` 只接收 `DrinkStory` 与请求状态，不直接访问外部服务。

## AI Drink Story 边界

- 浏览器只请求项目内 `/api/generate-drink-story`；外部服务地址、模型和 Key 只由服务端环境变量 `AI_API_BASE_URL / AI_MODEL / AI_API_KEY` 读取。
- `AI_API_KEY` 只允许位于 Git 忽略的 `web/.env.local`，示例文件保持空值；日志、源码、前端 Bundle 和错误响应均不得出现 Key。
- 服务端只接受已知配料 ID、整数比例、六维风味、`mood.valence` 与合法杯型，并限制配料数量、总比例、情绪范围、请求频率和上游超时。
- 上游采用 OpenAI-compatible `/v1/chat/completions` JSON 输出；当前模型为 `gpt-4o-mini`。输出必须经结构检查和长度截断后再返回页面。
- AI 不得修改 `DrinkState`；加载、成功、失败属于独立展示状态。失败仅允许重试，不生成本地回退酒名或故事。

## mixEngine 规则

- 风味和 RGB 使用配料百分比加权平均。
- 酒精度纳入 Alcohol 输出，所有输出归一化到 `0–1`。
- `totalPct === 0` 时返回稳定的安全默认值，不出现 `NaN`。
- `amountPct` 为整数，单次倒酒增加 1，合计最大 100。
- 计算函数保持纯函数，便于独立测试和后续 AI 配方复用。

## 指针与计时器规则

- 使用 Pointer Events 统一鼠标、触控和触控笔。
- 处理 `pointerdown`、`pointermove`、`pointerup`、`pointercancel`。
- 倒酒计时器只能存在一个；进入 Pour Zone 时启动，离开、松手、取消、Serve 和组件卸载时清理。
- 达到 100% 后立即停止计时器。
- 拖拽结束后恢复酒瓶视觉和原始位置。
- `RACK_INGREDIENTS` 只调整 19 种配料的混排顺序，仍引用 `INGREDIENTS` 的同一对象且不复制参数；所有配料由同一个酒柜层渲染，不再维护前台配料集合或分页状态。
- 左侧酒柜一次渲染全部 19 瓶，表现层按 7 / 6 / 6 三层错位定位。命中区可以相邻或轻微交叠，但键盘焦点、Pointer Events 与唯一倒酒计时器规则保持不变。
- `DragState.isPouring` 同时作为 Pour Focus 的唯一开关；松手、离区、取消、失焦、Serve 或满杯时必须退出。
- `PourZone` 保持唯一、稳定的语义命中容器：常态在容器内显示 `visualAssets.glassware[glassType]`，倒酒时由同一 `DragState.isPouring` 切换为 `DynamicGlass`；不得让位图透明区或原始像素尺寸决定命中范围。
- `PourZone` 的碰撞矩形、`.glass-visual-stack` 的常态资产尺寸和 Pour Focus 动态杯尺寸必须分别控制。缩放常态杯时不得同步缩小拖拽命中区。
- 酒柜层常态位于酒保之后；仅在存在 active bottle 时提升交互层。`IngredientBottle` 的拖拽缩放由统一 motion 状态控制：拿起阶段约为陈列态 `1.9x`，Pour Focus 约为 `2.6x`，名称与百分比在前景拖拽时隐藏。
- 背景资产加载成功时，常态 CSS `.counter` 回退层必须隐藏，避免覆盖背景中已有桌面；背景失败时才恢复 CSS 回退。该显隐只读取现有 `has-generated-background` / `has-fallback-background` 场景类。

## 可替换资产规则

- 场景、章鱼、瓶子与玻璃分别封装，禁止将完整画面烘焙成单张不可拆分背景。
- 组件通过稳定容器、`object-fit` 和语义化尺寸适配后续 WebP/PNG 资产。
- 资产路径集中管理；替换正式资产时不改业务状态逻辑。
- `web/lib/visualAssets.ts` 是视觉资产路径的唯一映射入口；组件中不散落硬编码路径。
- SVG/CSS 占位结构是 MVP 的必备回退层。生成的 PNG/WebP 只作为独立增强图层，加载失败时隐藏，不得导致场景、交互或信息缺失。
- 背景、酒保、八个酒瓶、四个常态杯具、动态酒杯和结果卡底板必须保持独立资产槽位；背景图不得包含角色、酒杯、酒瓶、Flavor Profile、按钮或文字。
- 四张常态杯具位图只负责容器外观；动态酒液与 Pour Focus 酒杯继续由 `DynamicGlass` 读取 `DrinkState` 渲染。位图加载失败时自动露出动态 SVG 回退，不新增状态分支。
- 用户提供的背景、吧台前景和八个配料瓶分别映射，禁止在组件里直接使用原始文件名。
- 19 个配料瓶均使用 `visualAssets.ingredientBottles` 按 `IngredientId` 映射；新增 11 瓶的数值口径同步 `docs/12-配料参数表.md`。
- 正式资产替换只允许更改集中路径和对应样式适配，不修改配方、拖拽、倒酒、Serve 或 WebMCP 逻辑。

## WebMCP 工具

新站点在浏览器支持 `document.modelContext` 时注册以下页面级工具，并复用与可见界面相同的状态和动作：

- `read_drink_state`：只读当前配方、风味和液体状态。
- `set_drink_recipe`：批量设置合法配方，总量按现有 mixEngine 规则限制为 100%。
- `serve_drink`：仅在混合阶段且杯中非空时执行 Serve，并等待结果卡完成显示。

不支持 WebMCP 的浏览器必须静默跳过注册，不能影响正常游戏。
