# 集中修改点索引

## 使用原则

大量推进时允许连续完成多个已确认阶段，但不能把参数、资产路径或流程入口分散到各组件。修改前先找到本索引中的唯一入口；新增修改点时同步更新本文件。

## 流程修改位置

| 要修改的内容 | 唯一或主要入口 | 说明 |
| --- | --- | --- |
| 满杯比例、单次增量、倒酒频率、Serve 时长 | `web/lib/gameConfig.ts` | 只改配置，不在组件中另写数字 |
| 配料名称、颜色、风味、酒精度、气泡、浑浊度 | `web/lib/ingredients.ts`、`docs/12-配料参数表.md` | 19 种配料的唯一代码数据源与参数文档 |
| 左侧三层酒柜混排 | `web/app/globals.css`、`web/components/IngredientShelf.tsx`、`web/lib/ingredients.ts` | 19 瓶一次渲染为 7 / 6 / 6；无分页和前台配料集合 |
| 配方归一化、混色、风味计算、100% 边界 | `web/lib/mixEngine.ts` | 保持纯函数并同步测试 |
| mixing / serving / result、拖拽和计时器生命周期 | `web/components/GameViewport.tsx` | 页面流程总编排入口 |
| 杯型列表、标签与默认杯型 | `web/lib/glassTypes.ts` | 杯型仅影响视觉 |
| Pour Focus 与中文当前配料 | `web/components/BarScene.tsx`、`web/components/PourZone.tsx` | 由 DragState 和配料数据驱动 |
| Pour Zone 命中、常态杯具与特写 SVG 切换 | `web/components/PourZone.tsx` | 命中范围不要绑定图片透明区；显隐只读取 `isPouring` |
| Serve 按钮 | `web/components/ServeControl.tsx` | 仅负责可见按钮，不自行改变配方 |
| 结果卡与重新开始 | `web/components/DrinkCard.tsx` | `MIX AGAIN` 通过父级回调重置统一状态 |
| Serve 后 AI 酒名/故事流程 | `web/components/GameViewport.tsx`、`web/lib/ai/generateDrinkStory.ts` | 冻结状态后并行请求；Abort、过期请求和重试统一在父级管理 |
| AI 服务端代理、校验与提示词 | `web/app/api/generate-drink-story/route.ts` | 读取服务端环境变量；不进入 mixEngine，不把 Key 或上游错误返回前端 |
| WebMCP 工具 | `web/components/GameViewport.tsx` | 必须复用可见界面的状态与动作 |

| BrightBridge 语音触发词与站内跳转 | `web/lib/bridge/navigation.ts` | 只维护一份触发词列表；目标固定为同域 `/` |
| BrightBridge 课程解析与前端 | `web/components/brightbridge/` | `/bridge` 路由只负责挂载，不复制状态 |
| BrightBridge 模型调用 | `web/lib/bridge/server.ts`、`web/app/api/bridge/*/route.ts` | Key 仅服务端可见，所有输入先校验 |

## 资产修改位置

| 要修改的内容 | 修改位置 | 禁止事项 |
| --- | --- | --- |
| 当前背景、吧台、角色、酒瓶和四种杯具文件路径 | `web/lib/visualAssets.ts` | 禁止在组件散落硬编码路径 |
| 背景内置桌面显隐与杯底对齐 | `web/app/globals.css` 中 `.scene.has-generated-background .counter`、`.pour-zone` | 背景成功时隐藏 CSS 回退；不得拆分或覆盖原背景桌面 |
| 常态杯尺寸、桌面位置与接触阴影 | `web/app/globals.css` 中 `.pour-zone`、`.glass-visual-stack`、`.glass-visual-stack::after` | 命中区和可见杯尺寸分离；不得通过改原背景解决 |
| 拖拽瓶前景尺度 | `web/components/IngredientBottle.tsx`、`web/app/globals.css` 中 `.ingredient-bottle.is-active` | 拿起与 Pour Focus 两级放大，酒柜陈列尺寸保持不变 |
| 倒酒液流、入杯连接与冲击反馈 | `web/components/PourStream.tsx`、`web/components/DynamicGlass.tsx`、`web/app/globals.css` 中 `.pour-stream` | 透明酒也必须具有可见动态反馈 |

| 单配料情绪参数与配方加权 | `web/lib/ingredients.ts`、`web/lib/mixEngine.ts`、`docs/12-配料参数表.md` | `moodValence` 为唯一参数源，范围 `-1..1` |
| 19 个用户提供瓶身与 Pour Focus 吧台前景路径 | `web/lib/visualAssets.ts` | 每项独立键名，保留 CSS 回退；吧台前景只在 `is-pour-focus` 中显示 |
| 本轮用户图片文件 | `web/public/assets/user-provided/2026-09-13/` | 原件语义化副本；替换时保留旧版本，禁止烘焙交互 UI |
| 四种常态杯具图片 | `web/public/assets/user-provided/2026-09-13/glassware/`、`web/lib/visualAssets.ts` | 仅替换容器外观；不得改变 Pour Zone、DrinkState 或 mixEngine |
| 旧版生成背景图片 | `web/public/assets/scene/` | 作为可回退/可复用旧稿保留，不直接覆盖 |
| 角色图片文件 | `web/public/assets/octopus/` | 优先透明 PNG/WebP，不带固定背景或道具 |
| 八个瓶子的占位结构 | `web/components/IngredientBottle.tsx` | 名称仍使用 HTML，不烘焙进图 |
| 动态酒杯 | `web/components/DynamicGlass.tsx` | 不绕开 DrinkState 写死液面和颜色 |
| 四种杯型的 SVG 轮廓与裁切 | `web/lib/glassTypes.ts`、`web/components/DynamicGlass.tsx` | 不进入 mixEngine |
| 结果卡底板 | `web/components/DrinkCard.tsx`、`.drink-card` | 配方和数字必须是实时 DOM 文本 |
| 视觉定位、尺寸、层级和透明度 | `web/app/globals.css` | 只调视觉，不改业务状态 |
| 顶部/底部薄型 HUD | `web/app/globals.css` 中 `.game-frame`、`.game-header`、`.control-deck` | 保持杯型和 Serve 至少 44px 触控命中 |

## 修改后的最低验证

1. 流程参数修改：运行 mixEngine 测试、TypeScript 检查和生产构建。
2. 资产或布局修改：生成 500×900 截图，检查酒馆识别、角色、酒杯、Flavor Profile、八瓶和 Serve。
3. 状态流程修改：验证空杯、倒酒、满杯、Serve、结果卡、`MIX AGAIN` 和计时器清理。
4. 将修改位置、验证结果和未完成真机项记录到当天开发日志。
