# 视觉资产替换规范

## 目标

当前 MVP 必须在没有正式美术资产时完整运行。SVG/CSS placeholder 是稳定回退层；生成图和未来正式资产是可选增强层。替换视觉资产不能改动配方状态、拖拽命中、倒酒计时器、Serve 或结果计算。

## 资产槽位

| 槽位 | 当前实现 | 资产路径或组件 | 替换要求 |
| --- | --- | --- | --- |
| 远景背景 | 生成 PNG + CSS 星空/城市回退 | `web/public/assets/scene/alien-tavern-background-v2.png` | 9:16；酒馆主体；不含角色、玻璃、UI、文字 |
| 机械章鱼 | 透明生成 PNG + CSS 拆分角色回退 | `web/public/assets/octopus/mechanical-bartender-v2-alpha.png` | 32-bit ARGB 透明背景；圆头多臂服务机器人；不含固定道具和背景 |
| 八个酒瓶 | CSS 结构化瓶身 | `IngredientBottle.tsx` | 每瓶独立；统一可视边界；名称仍由 HTML 提供 |
| 酒杯 | 动态 SVG | `DynamicGlass.tsx` | 液面和视觉参数必须继续由 DrinkState 驱动 |
| 结果卡底板 | CSS 分层面板 | `DrinkCard.tsx` 与 `.drink-card` | 不把配方、数字或文字烘焙到图片中 |

所有已接入的文件路径集中定义在 `web/lib/visualAssets.ts`。新增外部资产槽位时，先扩展该映射，再由对应组件读取。

## 图层与回退

1. SVG/CSS placeholder 先渲染，保证页面在图片缺失时仍可使用。
2. PNG/WebP 增强层加载成功后覆盖对应 placeholder；加载失败时增强层隐藏。
3. 背景、角色、吧台、酒瓶、酒杯、风味表、前景特效和结果卡保持独立 DOM 层。
4. 图片使用稳定容器、`object-fit` 和独立定位规则，不把像素坐标写入业务组件。
5. 交互命中区域绑定语义组件，不绑定图片透明区或图片内部构图。

## 新资产制作标准

- 色彩：黑、深青蓝、石墨灰为主；琥珀色用于少量焦点；蓝紫色用于稀疏全息光。
- 气质：高级、神秘、冷峻、生物机械；避免高饱和霓虹堆叠。
- 主题权重：酒馆设施、吧台工作位、杯具和酒架占主要信息量；外星城市、星球、舷窗与全息纹样只作次要点缀。
- 禁止：水印、品牌标识、装饰性乱码、固定配方数字、按钮和不可替换界面文字。
- 角色、酒瓶等前景对象优先透明 PNG/WebP；边缘不得出现明显底色或黑边。
- 背景需给中央 Pour Zone 和酒杯右侧 Flavor Profile 留出可读空间。
- 用户参考图保存在 `docs/references/robot-bartender-reference-2026-09-12.jpg`，仅用于圆头机器人、多机械臂和吧台工作关系，不得复制品牌、文字或具体商业产品造型。
- 参考照片只用于姿态、比例、材质或空间关系，不复刻可识别品牌、文字、商标和商业产品细节。

## 替换步骤

1. 检查目标槽位现有文件，禁止无意覆盖；需要保留旧稿时使用 `-v2` 等版本后缀。
2. 将资产放入 `web/public/assets/<slot>/`，所有项目资产只保存在 D 盘项目目录。
3. 修改 `web/lib/visualAssets.ts` 中对应路径，不改状态或交互代码。
4. 在 500×900 和实际窄屏尺寸检查遮挡、裁切、对比度与 Pour Zone 命中。
5. 模拟图片加载失败，确认 placeholder、完整调酒流程和结果卡仍可用。
6. 运行类型检查、数据测试和生产构建，并把结果写入当天开发日志。
