# 文档索引

## 阅读顺序

1. [开发需求](01-开发需求.md)：确认 MVP 做什么、不做什么。
2. [技术规范](02-技术规范.md)：确认代码结构、状态流和实现边界。
3. [设计规范](03-设计规范.md)：确认视觉语言、9:16 布局与交互反馈。
4. [执行步骤](04-执行步骤.md)：按小阶段推进，避免一次实现过多。
5. [验收标准](05-验收标准.md)：每个阶段完成后的检查依据。
6. [macOS 与 Xcode 说明](06-macOS与Xcode说明.md)：在 Apple/Mac 环境开发或后续封装时使用。
7. [可选参考项目](09-reference-projects.md)：只在遇到对应技术问题时查阅，不作为实现模板。
8. [视觉资产替换规范](10-视觉资产替换规范.md)：生成图、正式资产和 SVG/CSS 回退层的制作与接入标准。
9. [集中修改点索引](11-集中修改点索引.md)：流程参数、状态编排、资产路径和样式的唯一修改入口。

## 文档维护规则

- 产品行为变化：先改 `01-开发需求.md`。
- 数据、组件或工程结构变化：同步改 `02-技术规范.md`。
- 视觉、动效或操作反馈变化：同步改 `03-设计规范.md`。
- 阶段顺序或交付策略变化：同步改 `04-执行步骤.md`。
- 可测试行为变化：同步改 `05-验收标准.md`。
- 每次开发完成后：更新当天的 `开发日志/YYYY-MM-DD.md`。
- 参考项目与当前规范冲突时：以当前项目文档和用户最新需求为准。
- 新增或替换背景、角色、瓶子、酒杯、结果卡美术：遵循 `10-视觉资产替换规范.md`。
- 大量推进或调整流程前：先按 `11-集中修改点索引.md` 定位修改入口。

文档描述与实现冲突时，以最新确认的用户需求为最高优先级，并在当天日志中记录差异及处理方式。
