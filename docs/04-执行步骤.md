# 执行步骤

项目按小阶段推进。一次工作默认只处理当前阶段；只有当前阶段验证通过，才进入下一阶段。

## 阶段 0：项目基线

- 检查现有文件和 D 盘可复用依赖。
- 初始化 Next.js + TypeScript + Tailwind + Framer Motion。
- 创建 9:16 `GameViewport` 和基础主题变量。
- 验证开发环境可启动、桌面和移动尺寸无横向滚动。

## 阶段 1：数据与混合引擎

- 创建 Ingredient、DrinkState 等类型。
- 填写八种配料数据。
- 实现 `mixEngine`、`incrementIngredient` 和边界处理。
- 验证空配方、单配料、混合配料和 100% 上限。

## 阶段 2：酒杯与风味显示

- 实现 SVG `DynamicGlass`。
- 实现位于酒杯右侧的 Flavor Profile 全息面板；下方配料区不承载风味表。
- 使用固定测试配方确认液面、颜色、透明度、气泡和六项风味联动。

## 阶段 3：拖拽倒酒

- 实现酒瓶架、八个可拖拽酒瓶和 Pour Zone。
- 实现每 100ms 增加 1% 的单计时器逻辑。
- 实现离开、松手、取消、满杯和卸载清理。
- 验证鼠标与触控操作。

## 阶段 4：场景与角色

- 使用可替换 SVG/CSS 占位资产搭建七层场景。
- 通过集中资产映射为背景与角色接入可选生成图层，保留 SVG/CSS 加载失败回退。
- 实现机械章鱼拆分结构、待机动画与倒酒响应。
- 实现轻量视差、层级遮挡和低动态模式。

## 阶段 5：Serve 与结果卡

- 实现 Serve 启用条件和状态冻结。
- 实现场景压暗、酒杯转场和 Drink Card 展开。
- 显示已使用配料、百分比、风味数据和临时编号。

## 阶段 6：整体验收

- 按 `05-验收标准.md` 完整测试。
- 修复阻断流程、计时器、尺寸和可访问性问题。
- 确认结果页可通过 `MIX AGAIN` 清空配方并返回 mixing 状态。
- 确认流程参数和视觉资产均从集中修改点读取，不在组件内重复硬编码。
- 确认文档、日志和实现一致。

## 阶段 7：沉浸式场景交互升级

- 将八种配料瓶从底部迁移到后方酒柜，并接入独立瓶身资产与 CSS 回退。
- 底部改为四种杯型选择；杯型只传递到 DynamicGlass 与 Drink Card。
- 实现 Pour Focus、中文当前配料提示和 Flavor Profile 动态重点项。
- 扩展酒液的粘度、泡沫、波纹、冲击与混合扩散表现。
- Drink Card 增加杯型与配方比例分段可视化。
- 完成键盘、指针、Serve、MIX AGAIN、窄屏和资产回退回归验收。

## 阶段 8：常态杯具资产接入

- 将用户提供的四种杯具图片语义化复制到 D 盘项目资产目录，并集中映射到 `visualAssets.glassware`。
- 在同一个 Pour Zone 中实现“常态杯具位图 / Pour Focus 动态 SVG”的平滑切换，不改变命中区、配方状态或计时器。
- 验证杯型切换同步更新常态资产；图片加载失败时动态 SVG 自动回退；倒酒、松手恢复、Serve 与结果卡继续完整运行。

## 阶段 9：新增调料参数与三层酒柜混排

- 为 11 种新增调料建立语义资产副本、`IngredientId`、类别、风味、酒精和动态酒液参数。
- 将全部 19 种配料一次混排进三层酒柜，以 7 / 6 / 6 的错位布局保证每瓶都落在背景木架线上；移除分页与前台配料层。
- 验证新增高酒精、碳酸、高黏度和乳浊配料均由 mixEngine 正确加权，且 19 瓶同时渲染不影响配方和拖拽生命周期。

## 阶段 10：Serve 后 AI 酒名与故事

- 冻结最终配方后，与现有 Serve 演出并行请求文案，Drink Card 不等待网络返回。
- 建立独立客户端调用层与服务端代理路由，Key 仅存在于 Git 忽略的本地环境文件。
- 结果卡支持加载骨架、成功内容和失败重试；不提供预制回退文本。
- 使用网络 Mock 验收页面状态，再以真实本地路由进行一次供应商联调，避免自动回归重复消耗额度。

## 每阶段交付格式

1. 说明本阶段完成内容。
2. 列出实际验证及结果。
3. 更新当天开发日志。
4. 明确下一阶段，但不自动扩大实施范围。
