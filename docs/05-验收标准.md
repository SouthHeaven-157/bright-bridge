# 验收标准

## 基础显示

- 画布保持 9:16，桌面端居中，移动端不出现非预期横向滚动。
- 七个场景层级遮挡正确，无关键控件被前景覆盖。
- 19 种配料全部同时混排在左侧三层酒柜并按 7 / 6 / 6 落在对应木架线上；不使用分页、前台配料层或底部 Ingredient Array。
- 全部 19 瓶可聚焦、可拖拽，每个命中区不小于 44 × 44 CSS px；不要求规则等距，但不得悬空或落到层板之间。
- 酒柜瓶子周围不得出现额外矩形/圆角外框、黑色蒙层、内阴影或 CSS 假层板；背景图原有三层木架必须连续可见。
- 酒柜每排瓶底与对应木架承托线视觉贴合；瓶后不得出现 CSS 占位瓶重影。
- 酒保下半身稳定隐藏在前台之后；顶部 HUD 不高于 42px、底部 HUD 不高于 64px，杯型和 Serve 同行且按钮仍满足至少 44px 触控尺寸。
- 底部显示四种杯型缩略图，切换后吧台酒杯与结果卡外形同步，但配方、Flavor Profile 和 mixEngine 输出不变；控制区不重复展示主酒杯。
- 背景资产加载成功时不显示 CSS 假桌面，背景图原有木质桌面清晰可见；常态杯具资产杯底落在该桌面透视面内，不悬在分隔线、前台立面或控制区中。杯型切换后资产路径同步更新。
- 酒杯、位于酒杯右侧的 Flavor Profile 和 Serve 首屏可用；风味表不得遮挡 Pour Zone。

## 拖拽与倒酒

- 鼠标和触控均可抓取、移动、释放酒瓶。
- 只有进入 Pour Zone 才开始倒酒，频率为每 100ms 增加 1%。
- 离开 Pour Zone、`pointerup`、`pointercancel`、Serve 后立即停止。
- 快速点击、快速进出、连续切换酒瓶不会创建重复计时器。
- 单项和总量均为整数，总量不会超过 100%。
- 真正开始倒酒时进入 Pour Focus 并显示当前配料中文名；松手或离开 Pour Zone 后平滑恢复。
- Pour Focus 中常态杯具资产淡出、动态 SVG 酒杯淡入；退出后恢复常态资产。切换过程不改变 Pour Zone 命中范围、配方比例和倒酒频率。
- 常态杯具可见宽度不超过场景宽度的 22%，杯底位于场景高度 65%–72% 范围，且存在可见接触阴影；机械酒保仍是画面第一角色主体。
- 拿起酒瓶后其可见高度至少达到常态酒杯可见高度的 75%；进入 Pour Focus 后液流必须与杯口相交，酒液以每次 1% 持续增长并显示冲击波纹。
- Pour Focus 中只显示一个前景酒瓶；酒液路径包含弧线段，起点贴合倾斜瓶口、终点进入杯口，不得退化为悬空直线。
- 酒柜瓶身下方不得显示中文名称或 `0%` 等比例文字；倒酒时杯旁必须显示当前配料中文名。
- Pour Zone 的碰撞矩形在各状态下均不可见；截图中不得出现包围杯子和液流的蛋壳形虚线或大面积区域底色。
- 用户提供的吧台前景增强图只在 Pour Focus 可见，常态与结果阶段不得成为固定遮挡层。

## 数据与视觉

- 空杯状态无 `NaN`、负数或无效颜色。
- Flavor Profile 与当前配方同步，变化平滑且最终值正确。
- 新增 11 种调料的参数与 `docs/12-配料参数表.md` 一致；所有归一化参数在 `0–1`，RGB 通道在 `0–255`。
- 液面对应总比例；混色、透明度、浑浊度和气泡对应 mixEngine 输出。
- 酒液保持自然，不出现赛博纹理或不合理发光。
- 液流冲击、液面波纹、混合扩散、粘度、气泡与泡沫可见且不越出杯型裁切范围。
- Flavor Profile 平时弱化，倒酒时增强并突出当前变化最大的风味项。
- 杯旁和 Drink Card 中不得出现 Sweet、Sour、Bitter、Alcohol、Fresh、Body 等英文维度名；必须显示六个中文维度和一条“忧郁—喜悦”双向情绪轴。
- 空配方情绪值为 0；单配料等于其 `moodValence`；混合配方按百分比加权且结果始终位于 `-1..1`。
- 关闭、缺失或加载失败生成图层时，SVG/CSS 背景、角色、瓶子、酒杯和结果卡仍能支撑完整 MVP。
- 任一常态杯具图片加载失败时，对应动态 SVG 酒杯必须自动可见，用户仍可倒酒、Serve 和重新开始。
- 各视觉元素均可单独替换；替换背景或角色后不影响拖拽命中、混合数据和 Serve 流程。

## Serve 与结果

- 空杯时 Serve 不可用。
- 点击 Serve 后配方冻结，不能继续倒酒。
- 结果动画在 1.2–2.0 秒内完成，没有突跳或信息闪烁。
- Drink Card 只列出已加入配料，百分比和总配方一致。
- 卡片显示六项风味和临时编号。
- 卡片显示当前杯型，并以比例分段信息图展示配方组成；该图不伪装成杯中物理分层。
- Drink Card 在固定演出时长内出现，不等待 AI；AI 成功后显示非空的中文酒名、短句和 2～3 句故事。
- AI 加载时显示骨架且不覆盖配方内容；失败时只显示可操作的“重新生成”，不得出现硬编码回退故事。
- AI 输入只取冻结后的最终状态；请求期间继续拖拽、重置或过期请求不得把旧故事写入新一杯酒。
- 服务端拒绝未知配料、越界比例、无效风味/情绪/杯型；错误响应和前端 Bundle 不泄露 `AI_API_KEY`。
- 结果显示完成后可点击 `MIX AGAIN`，清空配方、恢复空杯并返回可操作的 mixing 状态。

## 工程质量

- 构建成功，无阻断运行错误。
- 浏览器控制台无持续报错或未清理计时器警告。
- 核心控件支持键盘聚焦并具有可读标签。
- `prefers-reduced-motion` 下体验可用。
- 当天开发日志已更新，待办和实际状态一致。
- `/` 情绪酒馆与 `/bridge` 智触心桥在同一端口返回 200，不需要同时启动第二个项目。
- BrightBridge 普通语音保留课程生成流程；包含“情绪酒馆”或配置负面情绪词时同域跳转 `/`。
